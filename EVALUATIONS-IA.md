# Génération d’évaluations de modules
Dans l’éditeur de formation, Contenu > Module > Évaluation interactive, ouvrir « Générer une évaluation avec l’IA ». Ajouter les objectifs spécifiques, choisir 2 à 20 QCM et la difficulté, sélectionner les ressources puis autoriser leur envoi. Les objectifs de formation, les leçons et la grille des compétences du module sont inclus automatiquement. Le texte des leçons est plafonné à 12 000 caractères par leçon ; le contexte total textuel est limité à 90 000 caractères (un contexte trop grand est refusé).

Sélectionner jusqu’à quatre PDF, images JPG/PNG/WebP ou fichiers TXT déjà déposés (15 Mo au total). Aucune ressource n’est sélectionnée à l’insu du formateur. Les audios, vidéos, liens, archives et documents bureautiques ne sont pas lus directement : fournir une transcription dans le champ dédié (20 000 caractères maximum) ou convertir en PDF. Les URL présentes dans les leçons ne sont pas consultées. Les descriptifs de ressources ne remplacent pas leur contenu.

Chaque question a quatre options, un corrigé, une justification, une compétence et une source à contrôler par le formateur. Le brouillon reste dans l’éditeur, invisible aux apprenants. Le JSON permet d’en modifier les champs ; « bonne » est un index de 0 à 3. Enregistrer le brouillon ou valider puis ajouter au quiz. Chaque question vaut un point ; seuil et progression utilisent le barème existant. Les simulations, réponses ouvertes et gestes pratiques ne sont pas générés dans cette version. Les QCM ne prouvent pas à eux seuls la maîtrise d’une compétence pratique.

La publication ajoute les questions sans supprimer celles existantes, supprime le brouillon et empêche une double publication. Un quiz HTML déjà actif bloque l’ajout IA. Un nouveau brouillon remplace le précédent ; la génération ne publie jamais automatiquement. Pour une formation déjà suivie, l’ajout de questions ne recalcule pas les résultats précédemment enregistrés : réserver la publication à la préparation pédagogique avant le début des évaluations.

## Render
La même OPENAI_API_KEY que les portraits est utilisée côté serveur. Le modèle texte par défaut est gpt-4.1-mini ; EVALUATION_AI_MODEL permet de choisir un autre modèle prenant en charge Responses, les images/PDF et les sorties JSON structurées. Le modèle d’image des portraits reste inchangé. Un quota API et l’accès au modèle sont nécessaires. EVALUATION_AI_DAILY_LIMIT définit le nombre de tentatives par formateur par jour UTC (5 par défaut, maximum 30). Une génération simultanée par module, deux sur le serveur, délai maximal 120 secondes. Les échecs API consomment une tentative. store:false est envoyé à l’API ; cela ne constitue pas une garantie de rétention zéro chez le fournisseur.

Les tests utilisent une API simulée. L’accès au modèle et la qualité réelle des questions restent à valider après déploiement. Les données d’apprenants ne sont pas ajoutées au contexte par l’application ; vérifier cependant le contenu personnel éventuel des documents avant envoi.
